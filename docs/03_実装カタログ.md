## 2. Terraform リソース

`infra/terraform/` は単一 environment 想定です。既定値は `project_id=mlops-dev-a`、`region=asia-northeast1` です。Feature Store 系は `google-beta` provider を使います。

| リソース | type | 備考 |
|---|---|---|
| 必要 API | `google_project_service` | AI Platform / BigQuery / Cloud Run / Artifact Registry / Storage |
| BQ dataset `feature_mart` | `google_bigquery_dataset` | 特徴量マート |
| BQ table `property_features_daily` | `google_bigquery_table` | `event_date` partition、`property_id` / `embedding_source` cluster |
| BQ view `v_property_features_emb_a` | `google_bigquery_table` view | `embedding_source = 'emb_a'` の Feature Group source |
| BQ view `v_property_features_emb_b` | `google_bigquery_table` view | `embedding_source = 'emb_b'` の Feature Group source |
| Feature Group `fg_property_emb_a` | `google_vertex_ai_feature_group` | BQ source は `v_property_features_emb_a`、Entity ID は `property_id` |
| Feature Group `fg_property_emb_b` | `google_vertex_ai_feature_group` | BQ source は `v_property_features_emb_b`、Entity ID は `property_id` |
| Feature × 7 × 2 | `google_vertex_ai_feature_group_feature` | 共通 4 + source 固有 3 |
| Artifact Registry repo `feature-store-offline` | `google_artifact_registry_repository` | Cloud Run job image 置き場 |
| Service Account `feature-store-offline-job` | `google_service_account` | Cloud Run job 実行 SA |
| Project IAM | `google_project_iam_member` | `bigquery.dataEditor` / `bigquery.jobUser` / `aiplatform.user` / `storage.objectAdmin` |
| GCS bucket `${project}-feature-offline-${region}` | `google_storage_bucket` | JSONL 出力先。14日 lifecycle、`force_destroy=true` |
| Cloud Run jobs | `google_cloud_run_v2_job` | `seed-csv` / `load-bq` / `register-fs` / `batch-read` |

## 3. BigQuery / Feature Store 構成

特徴量の実体は `feature_mart.property_features_daily` です。

| 列 | 型 | 役割 |
|---|---|---|
| `event_date` | DATE | partition |
| `feature_timestamp` | TIMESTAMP | feature-time |
| `property_id` | STRING | Entity ID |
| `embedding_source` | STRING | `emb_a` / `emb_b` lineage |
| `rent` | INT64 | 共通特徴量 |
| `walk_min` | INT64 | 共通特徴量 |
| `age_years` | INT64 | 共通特徴量 |
| `area_m2` | FLOAT64 | 共通特徴量 |
| `emb_a_ctr` | FLOAT64 | emb_a 固有 |
| `emb_a_fav_rate` | FLOAT64 | emb_a 固有 |
| `emb_a_semantic_score` | FLOAT64 | emb_a 固有 |
| `emb_b_inquiry_rate` | FLOAT64 | emb_b 固有 |
| `emb_b_collab_score` | FLOAT64 | emb_b 固有 |
| `emb_b_engagement` | FLOAT64 | emb_b 固有 |

Feature Group は embedding source 別に分けます。

| BQ View | Feature Group | Feature |
|---|---|---|
| `feature_mart.v_property_features_emb_a` | `fg_property_emb_a` | `rent`, `walk_min`, `age_years`, `area_m2`, `emb_a_ctr`, `emb_a_fav_rate`, `emb_a_semantic_score` |
| `feature_mart.v_property_features_emb_b` | `fg_property_emb_b` | `rent`, `walk_min`, `age_years`, `area_m2`, `emb_b_inquiry_rate`, `emb_b_collab_score`, `emb_b_engagement` |

Terraform でも BQ View / Feature Group / Feature を作成します。`register-fs` job も BQ View 作成と Feature Group / Feature 登録を行いますが、既存リソースは `409` を skip するため冪等確認として再実行できます。

## 4. Cloud Run job アプリ

`src/app/main.py` の dispatch table で、単一 image をコマンド分岐します。

| コマンド | モジュール | 機能 |
|---|---|---|
| `seed-csv` | `app.data.seed_csv` | 固定 5 物件の `feature_emb_a.csv` / `feature_emb_b.csv` を `data/` に生成 |
| `load-bq` | `app.data.load_bq` | CSV を読み、当日分を `DELETE` してから BigQuery へ `INSERT` |
| `register-fs` | `app.feature_store.register` | BQ View を作成し、Vertex AI REST で Feature Group / Feature を登録 |
| `batch-read-offline` | `app.batch.read_offline` | Feature Store REST API で Feature Group / Feature を取得し BQ View・Feature ID を解決。動的 SELECT で BigQuery offline read → stdout + GCS JSONL |

`seed-csv` / `load-bq` は次のデータディレクトリを使います。

```text
ローカル: src/data/
Docker:  /app/data/
```

Cloud Run job のファイルシステムは job 実行ごとに揮発します。`seed-csv` の生成結果は別 job の `load-bq` へ永続共有されないため、Cloud Run 上の `load-bq` は image に同梱された `/app/data/feature_emb_a.csv` / `/app/data/feature_emb_b.csv` を読みます。`seed-csv` は CSV 生成処理の確認用 job として扱います。

`load-bq` は `event_date = CURRENT_DATE("Asia/Tokyo")` の行を削除してから投入するため、同じ日に再実行しても重複しません。

## 8. 設計判断・既知の挙動

- Feature Store 利用範囲は Offline のみ。Online Store / Feature View / sync / fetchFeatureValues は作成・使用しない。
- 特徴量の実体は BigQuery。Feature Group / Feature は特徴量管理・メタデータ・参照レイヤーとして扱う。
- BigQuery では 1 テーブルに `emb_a` / `emb_b` を集約し、`embedding_source` で lineage を持つ。
- Feature Store では BQ View 経由で `emb_a` / `emb_b` の Feature Group を分ける。
- `batch-read-offline` は Feature Store REST API で Feature Group の `bigQuerySource.inputUri` を GET し、Feature 一覧を LIST してから動的 SELECT を組み立てる。Python 側に BQ table/view 名・column 名を直書きしない。
- Feature Group ID は **アンダースコア** のみ使用可能 (Vertex AI API 制約)。ハイフンは不可。
- Cloud Run jobs はすべて `deletion_protection=false`。`destroy` で撤去可能。
- `register-fs` は REST API を使う。LRO は polling し、既存 Feature Group / Feature は `409` skip。
- `batch-read-offline` の日付 directory は Python の `date.today()` で作る。BigQuery 側の抽出日は `CURRENT_DATE("Asia/Tokyo")`。
- `gcloud ai feature-*` は使わない。Feature Store 確認は GCP UI または Vertex AI REST API を使う。
