## 1. コマンド早見

```bash
make tf-init        # terraform init
make check          # ruff + terraform fmt -check + validate
make deploy         # AR apply → image build/push → terraform apply

make seed-csv       # Cloud Run job: feature_emb_a.csv / feature_emb_b.csv 生成
make load-bq        # Cloud Run job: BigQuery へロード
make register-fs    # Cloud Run job: BQ View + Feature Group / Feature 登録
make batch-read     # Cloud Run job: offline batch 取得 → stdout + GCS JSONL

make verify-bq      # BigQuery の embedding_source 別件数確認
make verify-gcs     # GCS の result.jsonl を確認
make destroy        # 全リソース撤去
```

既定値:

```bash
PROJECT_ID=mlops-dev-a
REGION=asia-northeast1
AR_REPO=feature-store-offline
IMAGE_TAG=latest
```

値を変える場合は Make 変数で渡します。

```bash
make deploy PROJECT_ID=your-project REGION=asia-northeast1
```

## 3. デプロイ手順

Cloud Run job は指定 image が存在しないと作成できません。そのため `make deploy` は次の順で実行します。

1. `make tf-apply-ar`
2. `make build-push`
3. `make tf-apply`

各段階の内容:

| フェーズ | 内容 |
|---|---|
| `tf-apply-ar` | Artifact Registry repository を先に作成 |
| `build-push` | `infra/Dockerfile` から linux/amd64 image を build して push |
| `tf-apply` | BigQuery / Feature Group / GCS / Cloud Run jobs など全リソースを apply |

`build-push` は次の image を作ります。

```text
{REGION}-docker.pkg.dev/{PROJECT_ID}/{AR_REPO}/feature-store-offline-job:{IMAGE_TAG}
```

## 4. 実行手順

### 4.1 CSV 生成

```bash
make seed-csv
```

Cloud Run job `seed-csv` が `feature_emb_a.csv` / `feature_emb_b.csv` を `data/` に生成します。Docker image には初期 CSV も同梱されていますが、この job で同じ内容を再生成できます。

注意: Cloud Run job のファイルシステムは job 間で共有されません。`seed-csv` の生成物は次の `load-bq` job へ永続化されないため、Cloud Run 上の `load-bq` は image に同梱された `/app/data` の CSV を読みます。

### 4.2 BigQuery ロード

```bash
make load-bq
```

Cloud Run job `load-bq` が CSV を読み、`feature_mart.property_features_daily` に投入します。

冪等性:

```text
DELETE FROM property_features_daily
WHERE event_date = CURRENT_DATE("Asia/Tokyo")

その後、emb_a 5 行 + emb_b 5 行を INSERT
```

### 4.3 Feature Store 登録

```bash
make register-fs
```

Cloud Run job `register-fs` が次を行います。

```text
1. BQ View v_property_features_emb_a / v_property_features_emb_b を作成
2. Feature Group fg_property_emb_a / fg_property_emb_b を Vertex AI REST で登録
3. 各 Feature Group に Feature 7 個を登録
```

Terraform でも同じ Feature Group / Feature は作成対象です。既存の場合、`register-fs` は `409` を skip して完了します。

### 4.4 Offline batch 取得

```bash
make batch-read
```

Cloud Run job `batch-read` が Feature Store REST API で Feature Group / Feature を解決してから、BigQuery offline read を実行し、stdout と GCS JSONL に出力します。

stdout 例:

```text
[offline-feature][emb_a] property_id=p001 rent=85000 walk_min=7 age_years=12 area_m2=32.5 emb_a_ctr=0.12 emb_a_fav_rate=0.03 emb_a_semantic_score=0.72
[offline-feature][emb_b] property_id=p001 rent=85000 walk_min=7 age_years=12 area_m2=32.5 emb_b_inquiry_rate=0.01 emb_b_collab_score=0.65 emb_b_engagement=0.4
```

GCS path:

```text
gs://{PROJECT_ID}-feature-offline-{REGION}/offline-batch/{YYYYMMDD}/emb_a/result.jsonl
gs://{PROJECT_ID}-feature-offline-{REGION}/offline-batch/{YYYYMMDD}/emb_b/result.jsonl
```

## 5. 検証

### 5.1 BigQuery

```bash
make verify-bq
```

実行 SQL:

```sql
SELECT embedding_source, COUNT(*) AS cnt
FROM `{PROJECT_ID}.feature_mart.property_features_daily`
GROUP BY 1
ORDER BY 1
```

期待値:

```text
emb_a  5
emb_b  5
```

### 5.2 GCS

```bash
make verify-gcs
```

`gs://{PROJECT_ID}-feature-offline-{REGION}/offline-batch/**/*.jsonl` を列挙し、先頭 3 行を表示します。出力がない場合は先に `make batch-read` を実行してください。

### 5.3 GCP UI

| 確認場所 | 見るもの |
|---|---|
| BigQuery | `feature_mart.property_features_daily`、`v_property_features_emb_a`、`v_property_features_emb_b` |
| Vertex AI → Feature Store | `fg_property_emb_a` / `fg_property_emb_b` と Feature 7 個ずつ |
| Cloud Run → ジョブ | `seed-csv` / `load-bq` / `register-fs` / `batch-read` の実行履歴・ログ |
| Cloud Storage | `${PROJECT_ID}-feature-offline-${REGION}` bucket と `offline-batch/` 配下 |

## 7. 注意事項

- このプロジェクトでは Online Store / Feature View / sync / Redis を作成・操作しません。
- `load-bq` は `CURRENT_DATE("Asia/Tokyo")` の行を削除してから INSERT します。CSV の `event_date` は固定値ですが、削除条件は実行日基準です。
- `batch-read` の BigQuery 抽出条件も `CURRENT_DATE("Asia/Tokyo")` です。投入日と実行日がずれると 0 行になる可能性があります。
- `batch-read` の GCS directory は Python の `date.today()` で作られます。実行環境のタイムゾーン差が気になる場合は、ログと BigQuery 抽出日を合わせて確認してください。
- Feature Store 系の確認に `gcloud ai feature-*` は使いません。GCP UI または Vertex AI REST API で確認します。
- Cloud Run jobs はすべて `deletion_protection=false` です。

## 8. コスト / teardown

主な課金対象:

- BigQuery dataset / table / query
- Artifact Registry image
- Cloud Run job 実行
- GCS bucket / object
- Vertex AI Feature Group / Feature 関連

撤去:

```bash
make destroy
```

撤去時の設計:

- BigQuery table は `enable_deletion_protection=false` が既定です。
- GCS bucket は `force_destroy=true` のため object ごと削除されます。
- Cloud Run jobs は `deletion_protection=false` のため destroy 可能です。

一時停止用の Online Store gate はありません。Online Store 自体を作らない設計です。
